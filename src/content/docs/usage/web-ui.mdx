Веб-интерфейс есть на Keenetic, Asus и MikroTik, на OpenWrt его роль играет [LuCI](/usage/luci/). Адрес — `http://<адрес роутера>:9099/`. Пароль на Keenetic и MikroTik необязателен: если пропустить его при установке, интерфейс открывается без входа. Задать, сменить или убрать его можно в [«Настройки» → «Сервис»](/usage/settings/#сервис), из консоли — `exodus passwd`, удалить — `exodus passwd -d` (на MikroTik — `/container shell exodus cmd="exodus passwd -d"`). На Asus вход — через веб-интерфейс Merlin. Интерфейс на русском и английском, со светлой и тёмной темой.

## Быстрый старт

<Steps>

1. **«Профили»**: добавьте подписку или загрузите файл профиля.
2. **«Статус»**: включите сервис, выберите профиль, в разделе «Устройства» выберите режим и устройства.
3. Нажмите **«Сохранить и применить»**.

</Steps>

## Статус

- **Сервис** на Keenetic и MikroTik: слева версии Exodus и ядра, профиль и состояние прокси (на MikroTik ещё подключение к RouterOS), справа — профиль, **кнопка включения**, «Автозапуск» и «Панель».
  - Кнопка включения показывает состояние сервиса: «Выключено», «Включается…», «Включено». Нажатие запускает или останавливает сервис сразу, без «Сохранить и применить», и работает без автозапуска.
  - **«Автозапуск»** запускает сервис при загрузке роутера.
  - Отдельной кнопки перезапуска нет: перезапускает «Сохранить и применить» или выключение и включение.
- **Сервис** на Asus: состояние, кнопки «Запустить», «Остановить», «Перезапустить» и «Панель», «Автозапуск».
- **Профиль**: подписка или загруженный файл, подсказка у поля объясняет и автозапуск. «Сохранить и применить» перезапускает сервис с выбранным профилем.
- Если провайдер подписки присылает анонс, сверху появляется блок с логотипом, текстом и кнопкой «Поддержка».
- **Устройства** — кто идёт через прокси:
  - **«Все, кроме выбранных»** — через прокси идут все, выбранные — напрямую (по умолчанию).
  - **«Только выбранные»** — через прокси идут только выбранные.

  Выбирать можно:
  - **сегмент сети** (домашняя, гостевая) — все его устройства;
  - **сеть Wi-Fi** — устройства, подключённые к ней сейчас, список синхронизируется каждые 30 секунд. На Keenetic это точки Wi-Fi, на Asus — радиомодули и гостевые сети этого роутера, без узлов AiMesh, на MikroTik — интерфейсы wifi, wireless и CAPsMAN;
  - **устройство** — по MAC, вместе с IPv4 и IPv6;
  - **«Добавить по адресу»** — MAC, IP или сеть вроде `192.168.1.0/24` для устройств, которых роутер не показывает. IP известного роутеру устройства сохраняется как его MAC, так что выбор следует за устройством при смене адреса.

  DNS следует выбору: проксируемые устройства спрашивают ядро, остальные — роутер. Если в настройках выключен перехват (**«Настройки» → «Прокси» → «Включить»**), выбор устройств не действует.

**«Панель»** — панель ядра: выбор прокси в группах, соединения, логи. На Keenetic и MikroTik у неё своя вкладка **«Панель»** в веб-интерфейсе, по умолчанию это [MIBoard](https://github.com/blagodaren/miboard); кнопка «Панель» в блоке «Сервис» ведёт на эту вкладку, над панелью — кнопки «Обновить панель» и «Открыть в новой вкладке». На Asus кнопка «Панель» открывает панель (по умолчанию Zashboard) в новой вкладке. Ядро скачивает панель при первом запуске, она доступна, пока сервис работает. Если веб-интерфейс открыт по HTTPS, а ядро отдаёт панель по HTTP, браузер не покажет её во вкладке — откройте её в новой.

## Профили

- **Подписки**: название, URL, URL информации, User-Agent, интервал обновления, «Отправлять HWID». Для каждой видны трафик, срок действия и время обновления; «Обновить» скачивает её сразу. Подробно о полях — [Подписки и профили](/usage/subscriptions/).
- **Файлы профилей**: загрузка, скачивание и удаление своих конфигов Mihomo.
- **«Полное обновление»**: удаляет всё, что скачали провайдеры текущего профиля, скачивает подписку заново и перезапускает сервис. Файлы локальных провайдеров сохраняются.

## Редактор

Правка файлов на роутере: mixin-файл, профиль запуска (только для чтения — перезаписывается при перезапуске), файлы профилей, подписки, провайдеры правил и прокси. «Сохранить» или «Сохранить и перезапустить».

## Логи

Лог Exodus и лог ядра. **«Отчёт для отладки»** собирает отчёт для issue: адреса серверов, пароли и ссылки подписок в нём скрыты, но проверьте его перед отправкой.

Логи хранятся в RAM, предел размера и очистка при остановке — в [«Настройки» → «Сервис»](/usage/settings/#сервис).

## Обновления

Версии Exodus и ядра: установленная и последняя, архитектура, свободное место. GitHub опрашивается не чаще раза в 6 часов, «Проверить снова» — сразу. Ядро сравнивается по версии, для Exodus есть два канала — **«Обновления Exodus»**:

- **Релизы** (по умолчанию) — обновление предлагается, когда на GitHub выходит релиз с более высокой версией, чем установленная.
- **Dev** — обновление предлагается при каждом изменении кода ветки роутера (изменения README не считаются), в том числе между релизами. Такой код может быть недоделанным.

Канал сохраняется сразу, без «Сохранить и применить», и проверка запускается заново. Устанавливается в обоих случаях код ветки роутера.

Строка **«Панель»** показывает установленную и последнюю версии панели. Последняя версия MIBoard и Zashboard спрашивается у GitHub (с gh-proxy — через него), установленную MIBoard сообщает сама; MetaCubeXD и YACD берутся из ветки и версий не имеют. Панель скачивает запущенное ядро, поэтому у неё своя кнопка «Обновить» в строке, обновление Exodus её не ждёт.

«Обновить» скачивает Exodus и ядро с GitHub в Entware, настройки, профили и подписки сохраняются, прокси перезапускается. Ядро и gh-proxy остаются те, что выбраны в установщике — чтобы их сменить, запустите [установщик](/install/options/) снова. **«Режим малого места на флеше»** удаляет текущее ядро перед установкой нового, если обновление падает из-за нехватки места; до установки нового ядра прокси не работает.

## Что нового

На Keenetic и MikroTik после обновления один раз появляется окно **«Что нового»**: изменения версий, вышедших после прошлой установленной. На канале Dev сверху показываются изменения ветки, ещё не вошедшие в релиз, и кнопка «Коммиты» со сравнением с прошлой установкой на GitHub. Снова открыть окно можно кнопкой «Что нового» в окне «О сборке» — оно открывается по версии в шапке. После новой установки окно не появляется.
