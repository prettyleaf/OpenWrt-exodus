## Variables

Options are passed as environment variables after `|`, before `ash` or `sh`:

<Tabs syncKey="platform">
<TabItem label="OpenWrt">

```shell
wget -O - https://raw.githubusercontent.com/prettyleaf/openwrt-exodus/main/install.sh | VERSION=v1.30.7 CORE=alpha ash
```

</TabItem>
<TabItem label="Keenetic">

```shell
curl -fsSL https://raw.githubusercontent.com/prettyleaf/openwrt-exodus/keenetic/install.sh | CORE=alpha PASSWORD=secret sh
```

</TabItem>
<TabItem label="Asus">

```shell
curl -fsSL https://raw.githubusercontent.com/prettyleaf/openwrt-exodus/asuswrt/install.sh | CORE=alpha sh
```

</TabItem>
</Tabs>

| Variable | Platforms | Meaning |
| --- | --- | --- |
| `CORE` | all | `meta`, `alpha`, `prizrak`, `prizrak-kroha` or `prizrak-kroha-upx` (the last two on OpenWrt only) — install this [core](#core) without asking |
| `GH_PROXY` | all | address of [gh-proxy](#if-github-is-blocked) with the token, e.g. `https://example.com/ghproxy/TOKEN`; `GH_PROXY=` downloads only directly, without the public mirrors |
| `LOW_SPACE=1` | all | remove the current core before installing the new one when there is little free space |
| `VERSION` | OpenWrt | a release instead of the latest one, e.g. `v1.30.7` |
| `SUBSCRIPTION` | OpenWrt | a link of a [subscription](#subscription-during-the-install): the installer adds it, downloads it to check it and makes it the profile |
| `PASSWORD` | Keenetic | password of the web UI on the first install, at least 4 characters. Without it the installer asks for one, Enter without a password leaves the web UI without a login |
| `REF` | Keenetic, Asus | a branch or a tag instead of `keenetic` / `asuswrt` |

The chosen core and gh-proxy are saved (`/etc/config/nikki` on OpenWrt, `/opt/etc/exodus/config.json` on Keenetic and Asus): the next runs of the installer and the update page use them.

## Subscription during the install

On OpenWrt the installer can add your subscription, then it does not have to be entered in LuCI after the install. Put the link in single quotes: links may have `&` and `?` in them, the shell cuts a link without quotes.

```shell
wget -O - https://raw.githubusercontent.com/prettyleaf/openwrt-exodus/main/install.sh | SUBSCRIPTION='https://example.com/sub/TOKEN' ash
```

- The link is checked before anything is installed: it starts with `https://` or `http://` and has no spaces. The output shows only the host of the link, not its token.
- After the packages and the core, the installer adds the subscription to the **Profile** page: in place of the placeholder subscription on a new install, as a new subscription otherwise. When the same link is added already, that subscription is used, its name and settings stay. HWID headers are on, like for a subscription added in LuCI.
- The subscription is downloaded at once to check the link and becomes the profile. Its name and expiry come from the provider.
- When Exodus is disabled, in a terminal the installer asks whether to enable it with this subscription (Enter is yes). Which devices go through the proxy is chosen on **App Config**.
- When the subscription does not download, the installer shows the lines of the log with the reason, and the subscription stays on the **Profile** page to fix the link. A running Exodus keeps its profile.

## Core

In a terminal the installer asks for the core, Enter keeps the current one. `CORE=` chooses it without asking.

| Core | `CORE` | What is installed |
| --- | --- | --- |
| Mihomo Meta | `meta` | the latest stable release of [MetaCubeX/mihomo](https://github.com/MetaCubeX/mihomo/releases) |
| Mihomo Alpha | `alpha` | the latest development build, [Prerelease-Alpha](https://github.com/MetaCubeX/mihomo/releases/tag/Prerelease-Alpha) |
| Prizrak-Core | `prizrak` | the latest release of [legiz-ru/Prizrak-Core](https://github.com/legiz-ru/Prizrak-Core/releases), a fork of mihomo, the default on a new install |
| Prizrak-Kroha | `prizrak-kroha` | the lighter build of Prizrak-Core from the same release for routers with little flash: about 35–40 MB on flash. OpenWrt only: amd64, arm64, armv7, mips, mipsle |
| Prizrak-Kroha UPX | `prizrak-kroha-upx` | the same build packed with UPX: about 8–10 MB on flash, unpacked into RAM when it starts |

The core is downloaded from its GitHub releases for the architecture of the router, the next runs of the installer and the update page update it to the latest build. Only the chosen core is written to flash: on OpenWrt since 1.31.0 no package carries it, Mihomo Meta is downloaded like the others, from the latest stable release. The `mihomo-meta` package of older versions is removed by the installer, its core stays and is updated.

## If GitHub is blocked

The installer first checks access to GitHub and tries the routes in turn:

1. the saved gh-proxy, if there is one;
2. directly. When GitHub does not answer, the installer prints the reason, for example `github does not answer directly: curl: (6) Could not resolve host`, see [troubleshooting](/en/troubleshooting/#the-installer-says-github-is-unreachable) for what it means;
3. on OpenWrt, through the GitHub API, when only `github.com` is blocked and `api.github.com` and `release-assets.githubusercontent.com` answer. The installer takes the metadata of the release from the API and downloads the files by their ids, nothing to set up, the output says `through the GitHub API`;
4. the public mirrors `gh-proxy.com` and `ghfast.top`. The mirror that worked is saved like your own gh-proxy, the update page downloads through it.

A public mirror could change the files it serves and nothing checks them: with a server of your own, prefer your own gh-proxy. `GH_PROXY=` makes the installer download only directly again (on OpenWrt also through the GitHub API), `GH_PROXY=<address>` only through that address.

When the mirrors do not answer either, the installer checks [jsDelivr](https://www.jsdelivr.com/): if jsDelivr is reachable, GitHub is blocked by the provider; if not, the router probably has no internet or DNS. jsDelivr serves files of the repository, but not release files, so the packages and the core come only from GitHub.

Then you need your own [gh-proxy](https://github.com/prettyleaf/gh-proxy) on a server that can reach GitHub. Its address with the token looks like `https://example.com/ghproxy/TOKEN`. In a terminal the installer asks for the address itself. It can also be given in advance, downloading the installer through the same gh-proxy or from jsDelivr:

<Tabs syncKey="platform">
<TabItem label="OpenWrt">

```shell
# through gh-proxy
wget -O - https://example.com/ghproxy/TOKEN/https://raw.githubusercontent.com/prettyleaf/openwrt-exodus/main/install.sh | GH_PROXY=https://example.com/ghproxy/TOKEN ash
# the installer from jsDelivr, it may lag behind the repository by a few hours
wget -O - https://cdn.jsdelivr.net/gh/prettyleaf/openwrt-exodus@main/install.sh | GH_PROXY=https://example.com/ghproxy/TOKEN ash
```

</TabItem>
<TabItem label="Keenetic">

```shell
# through gh-proxy

# the installer from jsDelivr, it may lag behind the repository by a few hours
curl -fsSL https://cdn.jsdelivr.net/gh/prettyleaf/openwrt-exodus@keenetic/install.sh | GH_PROXY=https://example.com/ghproxy/TOKEN sh
```

</TabItem>

- The address is saved, the next runs and the update page download through it. When the saved gh-proxy does not work, the installer tries to download directly, then through the public mirrors.
- If `GHP_ALLOW_LIST` of the gh-proxy is set, allow `prettyleaf/openwrt-exodus`, `MetaCubeX/mihomo` and `legiz-ru/Prizrak-Core` in it (on OpenWrt Mihomo Meta comes in the packages, `MetaCubeX/mihomo` is for Alpha), and `mikefarah/yq` on Keenetic, MikroTik and Asus. gh-proxy answers 404 to a wrong token and to a repository outside the list.
- On OpenWrt the packages can also be installed without gh-proxy, from the release archive: [installing without access to GitHub](/en/install/openwrt/#installing-without-access-to-github).
